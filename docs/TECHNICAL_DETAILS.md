# Technical Details

## Static Analysis

`ire_zero` safely unpacks each IPA, loads the main application bundle, parses `Info.plist`, and attempts entitlement and signing extraction. Tool use is intentionally explicit:

| Tool or component | Extraction performed |
| --- | --- |
| Python `plistlib` | Bundle identifier, name, URL types, ATS dictionary, query schemes, and injected synthetic metadata. |
| `codesign` | Entitlements and signing metadata when installed and applicable to the bundle. |
| Built-in Mach-O parser | Sections, segment names, addresses, offsets, flags, LC_BUILD_VERSION platform, and Shannon entropy per section. |
| `otool -L` | Linked dynamic libraries. |
| `otool -tvV` | Bounded textual disassembly evidence. |
| `nm -m` | Symbols when available for the binary. |
| `class-dump` | Objective-C class/interface text when the tool can process the binary. |
| Built-in string scanner and JSON rule pack | URLs, IPs, secret-like patterns, and suspicious keywords. |
| Ghidra `analyzeHeadless` | Optional symbol/import/export enrichment only when an executable Ghidra path is provided. |

`jtool2` is not invoked by the current code. Ghidra was disabled in the reported Mastodon baseline because no headless path was supplied; it is an optional integration rather than evidence underlying the reported score.

## Analyst Notes And Symbol Semantics

The UI label "AI Notes" currently presents deterministic evidence summaries generated by `ire_zero.semantics.synthesize_notes`. It does not call an LLM. The symbol classifier recognizes evidence categories through marker matching, including Swift mangled-symbol hints and Objective-C runtime markers. It does not recover Swift generic types, reconstruct Objective-C message chains, or perform LLM-based ARM64 decompilation. Private API findings are based on known private framework/API markers recovered from binary and rule evidence.

## Dynamic Layer

The stored live run uses Frida **17.9.11** with an authorized Mastodon companion build in the **iPhone 17 Pro Simulator**. The generated `frida-hooks.js` supports probes for:

| Probe group | Instrumented behavior |
| --- | --- |
| Network | `NSURLSession` requests and trust evaluation signals. |
| Storage | `SecItemAdd`, `SecItemCopyMatching`, `SecItemUpdate`, and preference access where planned. |
| Privacy/process | `UIPasteboard` access and application/scheme inspection probes where planned. |
| Crypto/tamper evidence | Common cryptographic exports and anti-analysis indicators selected from the probe plan. |

The capture schema distinguishes `exact_ipa`, `companion_build`, and `not_captured`. A companion build is valid runtime evidence about the built application behavior, but it is not represented as byte-identical execution of the uploaded IPA. `cross_layer_correlation()` produces a report-level `cross_layer` section and assigns each event one of three labels: `CONFIRMED` for exact static evidence, `DOMAIN_MATCH` for a dynamic URL sharing recovered static domain evidence without an exact URL match, and `DYNAMIC_ONLY` when no static counterpart is found. The captured Mastodon endpoint is `DOMAIN_MATCH`.

## Risk Scoring

CipherDock applies deterministic finding weights. A finding contributes according to severity (`critical=35`, `high=24`, `medium=14`, `low=6`, `info=1`) and confidence (`high=1.0`, `medium=0.75`, `low=0.5`), with each scoring bucket capped at 35 and the total capped at 100. Static buckets are transport security, hardcoded secrets, private API, jailbreak detection, suspicious network endpoints, entitlements, and symbol intelligence; confirmed risky runtime findings can add a dynamic-confirmation bucket.

There are no trained SHAP weights and no voting ensemble in the present implementation. For the Mastodon benign control, the principal contributions are transport security **14**, network endpoints **3**, symbol intelligence **1**, and zero contributions in hardcoded secrets, private API, jailbreak detection, entitlements, and dynamic confirmation, yielding score **18**.

## Evaluation Statistics And Reproducibility

`eval/run_all.py` writes `threshold_curve.csv` by reusing the same stable held-out split used in reported metrics and calculating precision, recall, and F1 at thresholds 10 through 95 in steps of 5. It writes `category_delta.csv` by applying a two-sided asymptotic Mann-Whitney U test with tie correction to benign and controlled-malicious category-count distributions. `eval/verify_corpus.py` independently checks IPA SHA-256 values against the label manifest and, for real benign controls, the SHA values recorded in `BUILD.md`. `eval/generate_summary.py` fills a concise summary solely from `evaluation_numbers.json`.

## Mach-O Evidence

The built-in parser accepts thin and fat Mach-O containers, preferring an ARM64 slice when present. It extracts `LC_SEGMENT_64` section records and `LC_BUILD_VERSION`, retains segment and section identifiers, virtual addresses, file offsets, sizes and flags, and calculates byte-distribution entropy for each extracted section. External disassembly and symbol tools add evidence when installed; absence of an optional tool is retained as coverage information rather than treated as a failed risk finding.
